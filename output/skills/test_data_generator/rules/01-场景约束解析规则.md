# 场景约束解析规则

> 适用于任务(a)：解析场景描述文本，理解条件约束并确定各字段赋值。

场景描述文本本质上是一组**条件约束**的集合，而非简单的"字段=值"映射。要求通读整段场景文本，完整理解其中所有约束条件及其之间的依赖关系（包括条件触发、约束叠加等），然后为每个字段生成**同时满足所有约束**且**符合现实实际情况**的值。

## 一、字段边界（适配当前 HEAD/BODY 快照）

- `request_snapshot.json` 是唯一字段来源；`HEAD` 对应步骤 `request_header`，`BODY` 对应请求体。两者各自以完整路径为键、当前值为默认值。
- 场景中的完整路径可直接匹配；只写末级字段名时，仅在 HEAD/BODY 合并后能唯一匹配，或上下文明确指定分区时才可使用。同名路径必须保留所属分区。
- 一个名称匹配到多个路径，或明确引用的字段不在快照中时，忽略该字段约束，不得猜测或新建字段。
- 输出不得包含快照之外的字段，也不得遗漏快照字段。
- 分析结果中的 `字段改动` 只返回本行需要修改的字段；未改动字段由后端按快照补齐。
- 本规则下文中所有"模板默认值"均指**同分区快照值**；"字段英文名"均指**HEAD/BODY 字段路径**。

## 二、约束类型识别指引

以下为常见类型，不限于此：

| 约束类型 | 说明                                 | 场景文本示例                                                       | 赋值指引 |
|---|------------------------------------|--------------------------------------------------------------|---|
| **直接赋值** | 字段被明确指定值，可能带有"传""录入"等动词            | `bosb传1`、`业务类型（bosb）传1`                                      | 直接使用指定值 |
| **必输/必填** | 字段需填写但刻意留空以触发校验                    | `bosc必输`、`bosc、bosd必输`                                       | 对应字段 = "" |
| **条件依赖** | 某字段取特定值（可能有值，也可能没值，即不赋值）时触发其他字段的约束 | `bosb传1，则bosc必输`、`A传X时B仅能为Y或Z`                               | 先确定前提字段值，触发后按条件约束目标字段 |
| **枚举值** | 字段只能取指定值之一                         | `类型仅允许A或B`、`bosc只能传1/2/3`                                    | 从允许值中选择（正流程选合法值，异常场景可超出） |
| **格式约束** | 字段值须符合特定数据格式                       | `身份证号格式`、`手机号格式`、`日期格式yyyyMMdd`                              | 生成符合格式规范的真实感数据 |
| **长度约束** | 字段值有长度限制                           | `长度不超过20位`、`最少8位`、`固定18位`                                    | 生成满足长度要求的真实感数据 |
| **字符约束** | 字段值允许或禁止某类字符                       | `不能包含英文`、`仅允许数字`、`不能含特殊字符`                                   | 在允许字符集内生成数据；**场景指定字符个数（含"一个/N个"等数量词）时，视为固定长度约束，生成值的字符数必须严格等于该个数** |
| **数值范围** | 字段值有大小要求                           | `金额大于0`、`年龄18-65`、`数量不超过100`、`录入符合…且大于A且小于B`、`录入不符合…大于A且小于B` | 在范围内生成合理数值 |
| **现实合理性** | 字段值需符合业务语义和现实逻辑                    | `姓名`、`银行卡号`、`车牌号`、`地址`                                       | 生成符合现实逻辑的数据，杜绝明显虚假 |
| **一致性约束** | 字段值须与参照基准保持相同或对应（等值约束）；参照基准可为报文中另一字段、场景指定值或系统/外部值 | `与营业日期一致`、`与户名（B字段）相同`、`证件号与出生日期匹配`                           | 先确定参照基准的值，本字段赋相同值；参照基准为另一字段时取该字段值，为场景直接指定值时使用指定值，为系统日期/时间或随生成时刻变化的值时必须使用系统提示词中服务端提供的 `Asia/Shanghai` 基准日期时间与 Unix 时间戳（见 `rules/04-字段数据生成规则.md` 3.5 节） |

## 三、条件依赖处理

场景中常见"如果……则……""当……时……""……前提下……"等句式。处理方式：

1. 识别前提条件（哪个字段取何值时触发）
2. 理解触发后的约束（目标字段需满足什么）
3. 在当前场景中，若前提确实成立，为目标字段应用对应约束；否则忽略该分支

## 四、约束叠加

同一字段可能受多条约束限制，需**同时满足全部约束**。若约束互相矛盾（极少出现），以后出现的为准。

## 五、分隔符与负号识别

场景文本中的 `-` 存在两种用法——作为中文分隔符（破折号/连字符，连接描述与值）或作为数学负号（表示负数）。当遇到 `传-X`、`录入-X`、`送-X` 等模式时，**必须结合上下文判断** `-` 的真实含义：

| 判断维度 | `-` 是分隔符 | `-` 是负号 |
|---------|------------|----------|
| **业务含义** | 字段为编码/类型/方式等标识类值（如还款方式、证件类型、利率形式），编码值通常为正数 | 字段为金额/利率/数值等，业务上允许负值（如贴息利率可以为负） |
| **同分区快照值** | 该字段的同分区快照值为正数（如 `bosrepayway` 默认为 `3`）| 该字段快照值本身可能为负或零 |
| **后缀说明** | `-` 后有中文描述补充（如 `传-3 等额本息`，"等额本息"是对 `3` 的解释） | `-` 后仅为数值，无中文补充说明 |
| **上下文句式** | 句式结构为"字段名 + 动作 + 分隔符 + 值 + 说明"，`-` 前后为不同语义单元 | 句式结构为"字段名 + 动作 + 负数值" |

**判定流程**：

1. 先看 `-` 后面是否紧跟中文说明（如"等额本息"、"身份证"等）→ 若有，`-` 大概率是分隔符
2. 再看字段的业务属性 → 编码/类型类字段几乎不会是负数；金额/利率类字段才可能是负数
3. 最后对照同分区快照值 → 快照值为正数的编码类字段，`-` 必为分隔符

**示例**：

- `bosa传-3 等额本息` → `-` 后跟"3 等额本息"，有中文说明，字段为还款方式编码，快照值为 `3` → `-` 是分隔符，值为 `"3"` **而非** `"-3"`
- `bosb传-12 等本等息` → 同上逻辑，值为 `"12"` **而非** `"-12"`
- `bosc录入-1.0` → `-` 后仅为数值无中文说明，字段为合同利率，业务上可能为负 → `-` 是负号，值为 `"-1.0"`

> **关键原则**：编码/类型/方式类字段的值几乎不会为负数。当看到 `传-X` 且字段是编码类，优先判定 `-` 为分隔符。

## 六、字段识别注意事项

- 提取的字段路径须在 `request_snapshot.json` 的 HEAD 或 BODY 分区中存在；不在快照中的字段约束可忽略
- "其他字段正常录入" = 未提及字段使用同分区快照值
